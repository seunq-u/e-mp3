# e-mp3

e-mp3 bot is music playlist ranking discord bot! xD

1. 플리를 만들어 공유 하거나 개인이 듣기
2. 공유된 플리에는 좋아요, 구독 등이 가능함
3. 플리는 봇으로 재생이 가능함 정도

## 용어

실시간 PICK 플리 -> 실시간으로 최근 24시간 내 하트가 가장 많은 플리  
월간 PICK 플리 -> 최근 1달(30일) 동안 인기 플리  
주간 PICK 플리 -> 최근 1주 동안 인기 플리  
이번달의 추천 플리 -> 매달 만들어 지는 추천 플레이리스트 (내가 직접 추가 해야됨)  

## 명령어 목록

/도움말 -> 도움말

/플리 -> 실시간 인기 플리 & 이번달의 추천 플리 1개 표시, 아래 버튼 (버튼 `🔍 자세히 보기`, `실시간 PICK! 플리 재생`, `PICK! 플리 더보기(/플리 PICK 링크)`)  
/플리 PICK -> 실시간 2개, 주간 & 월간 인기 플리 각각 1개씩 표시, (리스트 `위에 표시된 플리 재생`) (버튼 `실시간 PICK!`, `주간 PICK!`, `월간 PICK`)  -> (리스트 `표시된 플리 재생`)  
/플리 추천 -> 이번달의 추천 플리 표시, (버튼 `🔍 자세히 보기`, `🎶 재생하기`, `📜 저장하기`)  
/플리 관리 -> 내 플리 표시 상단에는 공유 + 하트 개수 표시, 하단에 개인 표시, (버튼 `플리 재생`, `플리 생성`, `곡 추가`, `플리 삭제`, `공유 설정`)
/플리 하트 -> 하트 누른 플리 표시 (리스트 `하트 누른 플리 표시` -> (버튼 `🔍 자세히 보기`, `재생`, `하트 취소`, `플리 저장`))  

## UI

플리 재생중에는 아래에 `중단`, `건너뛰기`, `점프`, `하트`, `저장하기`, `종료` 와 같은 버튼 표시  

## 데이터 저장

플리 데이터와 유저 데이터를 구분하여 저장하고,  
플리에는 각각의 고유 번호를 부여하여  
해당 플리를 가지고 있는 유저에겐 플리 ID를, 플리에는 유저 ID를 저장,  

* 날자 및 시간의 표기는 `년.월.일.시간.분.초.요일` 로 저장함

### 하트 수 집계 및 저장

1. 하트는 매일 자정에 집계함  
    * 집계중에는 PICK을 확인할 수 없으며, PICK 및 추천 플리의 하트추가 와 같은 기능을 이용할 수 없음  
    * 따라서 `/플리 PICK`, `플리 하트` 은 사용시 불가 메세지, `/플리` 는 위는 불가, 이번달의 추천 플리만 표시함  
    * 및 기타 하트 표시 기능에서도 `집계중..`이라 표시함  

2. 하트의 저장
    * 하트는 Today(Integer) 와 Last(Obj) 그리고 All(Integer)의 세 변수로 플리 데이터 내부에 저장함
    * Today 는 당일의 하트수를 기록함  
    * Last 이전의 모든 수를 기록함  
    * 집계중에는 Today 를 0으로 초기화 시키며, Last 작일 날짜와 함께 하트를 기록, all 에 Today 값을 더함  
    * week (7일) 와 month (31일) 계산후 week, month 에 대입함

3. 비공개 플리의 집계
    * 비공개 플리도 함께 집계함
        * 왜냐하면 오전에 하트를 받고, 오후에 소유자가 비공개로 바꿀 수 도 있기 때문에

4. 집계 후작업
    1. 모든 플리의 week, month 집계하여 순서를 매김
    2. 실시간 PICK 초기화

5. 실시간 PICK 플리의 집계 방식
    * 하트를 누르면 플리에도 추가 되고, 집계 데이터(total.json) 에도 추가 함

### 플리의 저장 및 백업

1. 플리의 저장  
    * 플리는 저장시 Obj 형식으로 저장함  
    * 플리에는 `이름`, `아이디`, `설명`, `소유자`, `공개여부(Visibility)`, `최초 작성 날짜`, `최종 수성 날짜`  
    * 공개여부(Visibility) 는 0 -> 비공개, 1 -> 공개 처리함  
    * 플리에 음악 저장시 `제목`, `영상 url`, `시간`, `제작자`, `제작자 채널 url`, `미리보기 이미지 url`을 저장함  

2. 플리의 백업  
    * 플리는 하트수 집계시간마다 백업되며 최대 1주일 까지 백업됨  

### Json 형식

플리 데이터와 유저 데이터 및 집계 데이터는 각각 다음과 같은 방식으로 저장함.  

1. 플리 데이터  

    ```json (playlist_id.json)
    {
        "name" : "<플리 이름>",
        "description" : "<플리 성명>",
        "playlist_id" : "<플리 고유 ID>",
        "owner_id" : "<소유자(유저) 디스코드 고유 ID>",
        "visibility" : "<공개여부|0:비공개/1:공개)",
        "first_date" : "<플리 최초 작성 날짜 및 시간>",
        "last_date" : "<플리 최종 수정 날짜 및 시간>",
        "music" : [
            {
                "title" : "<음악의 제목>",
                "link" : "<음악의 url>",
                "time" : "<음악의 총 길이>",
                "author" : "<제작자>",
                "author_link" : "<제작자 url>",
                "thumbnail" : "<미리보기 이미지 url>"
            }
        ],
        "heart" : {
            "today" : 0,  // 당일 받은 하트 수
            "last" : [
                {"년.월.일.시간.분.초.요일" : 0} // `년.월.일.시간.분.초.요일` 에 받은 하트 수
            ],
            "week" : 0, // 주간 인기 (7일 기준)
            "month" : 0, // 월간 인기 (31일 기준)
        }
    }
    ```

2. 유저 데이터 (user_id.json)

    ```json
    {
        "user_id" : "<소유자(유저) 디스코드 고유 ID>",
        "playlist" : [
            100000000000, // playlist id
            100000000001,
        ]
    }
    ```

3. 집계 데이터 (total.json)

    ```json
    {
        "live" : [
            100000000000,
        ], // 실시간 인기 플리
        "week" : [
            100000000000,
        ], // 주간 인기 플리
        "month" : [
            100000000000,
        ], // 월간 인기 플리
    }
    ```

## config 설정

* `start_total` : `True/False` : 봇의 시작시 집계 여부
* `end_total` : `True/False` : 봇의 종료시 집계 여부
